Payload-footprint model
-----------------------
Conventional two-buffer copy handoff: approximately 2N payload bytes resident.
Shared backing handoff: approximately N payload bytes + small metadata.
Step 10 benchmark explicitly reports 0 tensor payload bytes copied by SHARE/MAP.

Benchmark interpretation boundary
---------------------------------
The current mapping subsystem records domain-local logical virtual mappings but
DOES NOT install distinct hardware page tables. The SHARE/MAP timings therefore
measure host-side kernel metadata operations only. They omit syscall transitions,
context switches, MMU page-table installation, TLB shootdowns, IOMMU/device
programming, scheduler wakeups and NUMA effects. The large numerical latency
ratios against memcpy MUST NOT be reported as end-to-end Nexora application
speedups. They demonstrate the expected scaling distinction: memcpy is O(N)
with payload size, while capability/mapping metadata is approximately O(1) with
respect to payload size in this prototype.

Remaining architectural boundaries
----------------------------------
- No user mode/syscall ABI yet.
- No hardware per-domain page tables/MMU enforcement yet.
- No IOMMU/device isolation yet.
- No real kernel APIC/SMP startup yet; host pthread tests exercise the same metadata structures.
- Spinlocks are not IRQ-save/preemption-aware.
- Revocation is local-token, not transitive capability-lineage revocation.
- WORK/GENERIC handle objects do not yet have managed lifetime hooks.
- Bump-allocator reclamation is logical; physical page recycling awaits a frame allocator/heap.
- Overlapping shared tensor writes require higher-layer synchronization/fence semantics.
