04 · Implemented

What the kernel already has.

The current x86-64 path contains enough low-level machinery to test privilege and ABI concepts, but not yet enough to claim a production userspace execution model.

BOOT

Multiboot2 + long mode

The assembly entry preserves the Multiboot information pointer, creates early page tables, enables long mode and transfers control into the 64-bit kernel.

PRIVILEGE

GDT, TSS and IDT

Kernel/user selectors, TSS.rsp0 and a 256-entry IDT establish the intended privilege boundary. Double faults use a dedicated IST stack.

SYSCALL

SYSCALL / SYSRET path

The kernel configures MSRs, saves user state through a BSP per-CPU record and checks unsafe return RIP/RFLAGS before SYSRET.

MEMORY

Frame + slab allocation

A bitmap frame allocator and slab caches support kernel objects. Excess completely free slab pages can be returned to the frame allocator.

ELF64

Strict image validation

The loader validates headers, machine type, segment bounds, W^X, overlap, entry placement, alignment and integer-overflow conditions.

FAULTS

Fail-closed exceptions

Recoverable fixups can redirect selected kernel faults. Unhandled kernel faults no longer return to the faulting instruction; fatal user faults mark the process dead in host tests.

05 · Boundary

Where the current implementation stops.

Several pieces exist independently, but the missing process-memory layer prevents them from forming a complete user-program execution path. This is the most important architectural boundary to understand in the current repository.

Already concrete
01

ELF64 validation can decide whether an image is structurally acceptable.

02

GDT/TSS/IDT and syscall MSRs establish the low-level privilege transition machinery.

03

User-address checks, handle tables and ABI structures exist and are exercised in host tests.

04

Fault handlers now fail closed rather than retrying unrecoverable instructions indefinitely.

Still required
01

Per-process page tables and a real VM mapper for ELF segments and user stacks.

02

A runnable-process scheduler capable of switching away from terminated or blocked user contexts.

03

Reference-counted kernel objects so delegated handles cannot outlive underlying resources.

04

Real tensor backing storage and controlled user mappings rather than metadata-only tensor objects.

06 · Fault model

Exception handling should make progress or stop safely.

The original audit identified a dangerous pattern: an unrecoverable fault handler could return and immediately execute the same faulting instruction again. The current path distinguishes fixup-capable faults from fatal exceptions.

Kernel fault + fixup

A registered fixup can rewrite the saved RIP and continue through a controlled recovery path.

Kernel fault, no fixup

The handler fails closed rather than IRET-ing back into an unrecoverable kernel instruction.

User fault

The process is marked dead; the next major step is scheduling another runnable process instead of stopping the research kernel.

07 · Next

The next boot milestone is a real process address space.

More assembly is not the main need. The next milestone is the glue between the validated ELF parser, physical allocator, privilege structures and scheduler: a coherent virtual-memory/process model.

Create per-process page tables

Define page-table ownership, kernel mappings, user ranges, teardown, TLB semantics and address-space switching.

Map validated ELF segments

Allocate frames, copy file-backed bytes, zero BSS, enforce W^X and roll back cleanly if any mapping step fails.

Construct a user stack

Map stack pages with guard regions and define the initial ABI contract for entry state and future argument passing.

Enter Ring 3 for real

Use the existing privilege structures to transfer to a mapped ELF entry with a mapped user stack and observable syscall round-trip.

Handle fatal user faults by scheduling

Terminate the faulting process, release owned handles/resources, select another runnable context and resume kernel progress.
