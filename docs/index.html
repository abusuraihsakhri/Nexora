AI-Native Operating System & Semantic Resource Architecture

Nexora is engineered around semantic knowledge of AI workloads rather than conventional process, page, and device abstractions alone. By exposing computational graphs, tensor lifecycles, model residency, and accelerator topologies directly to the kernel, Nexora achieves whole-system execution efficiency across heterogeneous CPU, GPU, NPU, and memory domains.

"An operating system that understands computation graphs, tensor lifetimes, model state, accelerator requirements, topology, data locality, deadlines, and resource capabilities can manage AI workloads more efficiently than an operating system that sees primarily processes, virtual pages, files, and devices."

The Eight Core Nexora Primitives

The foundational semantic abstractions through which the kernel coordinates AI compute, memory, and security.

NXTensor Primitive 1
Semantic data object with OS-visible dtype, shape, size, location (RAM/HBM), lifetime, mutability, reuse hints, and producer/consumer tracking.
Lifetime-aware allocation & reclamation
NXWork Primitive 2
The fundamental schedulable semantic unit. Defines operation type, input/output tensors, dependencies, deadlines, priority, and resource requirements.
Sits above threads as AI task unit
NXGraph Primitive 3
Directed dependency computation graph allowing the OS to determine what can execute, what must wait, and what memory can be immediately freed.
Enables early graph-aware garbage cleanup
NXState Primitive 4
Persistent semantic resources beyond ephemeral tensors (e.g. loaded model weights, KV caches, LoRA adapters, session and persistent agent state).
OS-managed model residency & zero cold-start
NXResource Primitive 5
Common unified abstraction making CPUs, GPUs, NPUs, HBM, RAM, NVMe, and NICs queryable through a single common resource model.
Heterogeneous compute fabric
NXTopology Primitive 6
Hardware interconnect graph capturing latency, bandwidth, NUMA distance, PCIe hierarchy, and direct accelerator accessibility.
Minimizes cross-bus data movement
NXCapability Primitive 7
Explicit unforgeable resource authority granting fine-grained execution, memory, model, and network delegation with explicit constraints.
Capability-based agent & process security
NXScheduler Primitive 8
Holistic multi-factor scheduler evaluating execution time, transfer cost, queue delay, memory pressure, deadline penalties, and topology.
Cost = Time + Transfer + Queue + Pressure

Two-Implementation Strategy

Bridging bare-metal systems research with real-world accelerator benchmarking.

Track 1 Nexora-RK (Research Microkernel)

A standalone, bare-metal x86_64 microkernel engineered for foundational systems research, hardware-enforced privilege isolation, and memory-safety mechanisms.

  • Boots via Multiboot2 on bare-metal and QEMU x86_64
  • Hardware-enforced Ring 0 / Ring 3 privilege isolation (GDT/TSS)
  • Dedicated per-CPU %gs stack frames for fast syscall/sysret
  • Physical buddy/bitmap frame allocator with slab reclamation (M1 & M2)
  • Zero-panic user memory copy with .fixup_table exception recovery

Track 2 Nexora-X (Experimental Co-Kernel)

A Linux-hosted co-kernel and runtime environment designed for rapid experimentation and benchmarking against production accelerator hardware.

  • Runs alongside PyTorch, JAX, vLLM, and SGLang workloads
  • Interfaces directly with CUDA, ROCm, and OpenXLA / PJRT backends
  • Evaluates multi-model LLM inference under real HBM/GPU pressure
  • Tests DAG-aware tensor reclamation and multi-priority work dispatch
  • Mature mechanisms migrate directly down into Nexora-RK

Competitive Boundaries & Non-Goals

Defining what Nexora is, what it deliberately avoids, and where it interfaces with existing systems.

System Primary Focus Nexora's Strategic Separation
Linux General-purpose OS (processes, threads, pages, cgroups). Nexora exposes OS-level AI semantics; does not recreate hundreds of general device drivers.
LithOS Fine-grained spatial scheduling inside the GPU. Nexora targets whole-system (CPU + GPU + NPU + RAM + HBM + Fabric) semantic orchestration.
NVIDIA Dynamo Distributed generative-AI inference router. Dynamo operates at the inference-routing level; Nexora operates beneath it as the host resource engine.
NVIDIA Run:ai Cluster AI workload pooling and orchestration. Run:ai governs cluster allocations; Nexora coordinates machine-level execution and memory.
OpenXLA / PJRT Framework-independent hardware device API. Nexora integrates PJRT device backends directly into its semantic resource fabric.
AIOS LLM agent facilities running above an OS. AIOS sits above the host OS; Nexora provides the underlying capability-managed kernel.

Research Hypotheses & Target Workload

Evaluating Nexora through rigorous, measurable systems experiments.

H1 — Semantic Tensor Lifetime

Producer/consumer DAG tracking allows Nexora to reclaim temporary tensors early, reducing peak memory by ≥15% compared to lifetime-blind allocators.

H2 — Locality-Aware Scheduling

Topology-aware placement minimizes expensive cross-bus data movement, reducing host-to-device and device-to-device transfers by ≥20%.

H3 — Graph-Aware Scheduling

Dependency-aware dispatch over multi-priority queues reduces p99 tail latency compared to independent FIFO task scheduling.

H4 — Shared Tensor Handles

Zero-copy capability-protected shared backing eliminates cross-process memory duplication without sacrificing security boundaries.

H5 — Persistent Model State

Treating weights and KV caches as OS-managed persistent resources measurably slashes model cold-start times and time-to-first-token (TTFT).

Target Workload

Multi-model LLM inference on a single heterogeneous machine: dynamic concurrent requests, shared KV caches, high memory pressure, and CPU/GPU/NPU coordination.

The Four Project Rules

Every major architectural abstraction introduced into Nexora must answer four mandatory questions:

1. Problem: What existing problem does this solve?
2. Limitation: Why can't the current runtime layer solve it adequately?
3. Necessity: Why should the operating system know about it?
4. Metric: What measurable improvement results?
